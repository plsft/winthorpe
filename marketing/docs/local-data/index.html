Local data & security

Where everything lives, what's encrypted, what leaves your machine.

Where data lives

Everything Winthorpe stores is under %LOCALAPPDATA%\Winthorpe\ on Windows. Inside:

  • winthorpe.db — SQLite database. Workspaces, sessions, chat transcripts, settings, cost ledger.
  • workspaces/<repo>/<name>/ — git worktrees per workspace.
  • logs/rust.jsonl + .1 backup — structured JSONL logs (10 MB each, total bounded at 20 MB).
  • transcripts-processed.json — bookkeeping for the cost-ledger scanner.

Programs & bin (used by the CLI shim install): %LOCALAPPDATA%\Programs\Winthorpe\bin\.

Credentials

API keys and OAuth tokens for Anthropic and OpenAI providers go through Windows DPAPI (CryptProtectData / CryptUnprotectData) before being written to SQLite. DPAPI binds the encryption to your Windows user account — only your user can decrypt them, not other accounts on the same machine.

Claude Code's own OAuth tokens live where Claude Code puts them (~/.claude/.credentials.json) — Winthorpe reads them for the plan-usage panel but never re-stores them.

No telemetry

Winthorpe makes no analytics, no crash-reports-home, no "phone-home" requests. The only outbound network traffic is the one you trigger by talking to your agent (Anthropic's API, OpenAI's API, GitHub's API, optional updater check).

Network requests Winthorpe makes

  • Anthropic / OpenAI when you talk to Claude Code or Codex — direct from the bundled CLIs to the providers under your account.
  • GitHub for OAuth Device Flow + repo listing + PR creation via bundled gh.
  • GitLab via bundled glab, only if you authenticate it.
  • Anthropic OAuth usage endpoint for the Plan usage panel (Max / Pro users only). Throttled, cached.
  • github.com/plsft/winthorpe/releases for the updater check (you can disable it).

SQLite tuning

WAL mode, 256 MB mmap, 20 MB cache, prepared-statement cache, separate read/write connection pools with read-only flags on the read pool. Reads never block writes; writes never block reads. (See src-tauri/src/models/db.rs::init_connection.)

Backups

SQLite is one file. Back it up via Windows File History, OneDrive folder, or just copy %LOCALAPPDATA%\Winthorpe\winthorpe.db <destination>. WAL mode means a hot copy is consistent.
