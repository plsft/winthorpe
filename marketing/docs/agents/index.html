Agents & sessions

Claude Code and Codex, side by side.

Bundled agents

Winthorpe ships with both Claude Code (Anthropic) and Codex (OpenAI) CLIs included. No separate install. The Bun sidecar hosts both via their respective SDKs.

Sign-in

Onboarding includes a step that runs the appropriate claude /login or codex login command in an embedded PTY. You do the OAuth in your browser, the CLI writes its own credentials to ~/.claude/.credentials.json or ~/.codex/auth.json. Winthorpe reads these files for plan info but never re-stores or re-issues your tokens.

Model selection

The composer's model picker shows every model the bundled CLIs report as available, grouped by provider. Picking a model writes the selection to the session row in SQLite — so reopening the workspace, restarting the app, or switching workspaces and back, all preserve the choice. (This was a real bug we fixed: in earlier builds the picker was in-memory only and reset to Opus 4.7 on reload.)

Switching agents per workspace

Each workspace has its own session and its own model. You can run Claude Sonnet in workspace aldebaran and Codex gpt-5 in workspace vega at the same time — each session is fully isolated, both processes are tracked in their own Win32 Job Object so a kill or app close reaps them cleanly.

Skills (Anthropic Agent Skills)

Drop a directory under .claude/skills/<name>/ with a SKILL.md at its root and Claude Code picks it up. Scripts can be in any language — TS, Python, bash. The skill's frontmatter description tells Claude when to use it.

Sessions persist forever (until you delete them)

Every chat is stored in SQLite at %LOCALAPPDATA%\Winthorpe\winthorpe.db. Archiving a workspace doesn't delete its sessions — the transcript is still there if you ever restore the workspace.
