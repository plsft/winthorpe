Workspaces & worktrees

Conductor / workspace / worktree model.

The model

A Conductor is one of your git repos that Winthorpe knows about. A workspace under a conductor is a real git worktree add — its own working directory, on its own branch, independent of any other workspace under the same conductor.

This means you can have three Claude or Codex sessions running simultaneously against the same repo, each in its own branch and folder, and switching between them is a sidebar click. No git stash, no "let me commit my WIP first."

Workspace names

Names are auto-generated from a curated list of stars, moons, and constellations (achernar, aldebaran, andromeda, betelgeuse, vega, ursamajor…). Each name is unique per conductor and stable for the workspace's lifetime. The branch is <branch-prefix>/<name> by default.

Why random celestial names: memorable, collision-free, doesn't leak intent (you can spin up a workspace before you've decided what it's for). The full list lives in src-tauri/src/workspace/helpers.rs::WORKSPACE_NAMES.

Status groups

Sidebar groups workspaces by status:

  • In progress — the active default. Newly-created workspaces land here.
  • In review — when a PR is open against it.
  • Done — PR merged.
  • Backlog — paused work.
  • Archived — worktree removed; chat transcript preserved for reference.

Archive

Archive a workspace and Winthorpe atomically: stops the FS watcher for that workspace, kills any open PTY scripts tagged with it, removes the worktree, deletes the local branch, moves the workspace to Done. Chat transcripts and session metadata stay in the local SQLite for reference. The on-disk workspace folder is renamed to .trash-<name>-<pid> first (instant), then deleted in the background — so the UI returns immediately even on huge repos.

Windows-specific: fs::rename can fail if any process holds a handle inside the dir (Defender, an open editor, the FS watcher). Winthorpe retries with backoff (50ms → 1.5s) and surfaces the actual OS error if every attempt fails.

Where workspaces live on disk

Worktrees are created under %LOCALAPPDATA%\Winthorpe\workspaces\<repo>\<workspace-name>\. The conductor's main checkout stays wherever you imported it from — Winthorpe doesn't move your existing repo.
