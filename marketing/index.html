Why Winthorpe

Built for the way you actually ship code with agents.

Parallel worktrees

Every workspace is a git worktree, every agent runs in its own. Refine an API contract in one workspace while the database migration runs in another — no branch-juggling, no merge conflicts.

Built-in Monaco editor

Edit any file the agent touches — or any file at all — without leaving the app. Multi-tab, full syntax highlighting, drag-to-reorder, Ctrl+S to save with toast confirm. Tokyo Night by default.

Real PTY, real Windows

ConPTY-backed terminals everywhere — vim, htop, ssh, claude, codex all work. Win32 Job Objects guarantee no orphaned children. DPAPI-protected credentials. No WSL required.

Cost & tokens, accurate

Per-turn token + API-equivalent cost ledger, pulled from authoritative JSONL transcripts. Live Plan usage for Claude Max / Pro (5h + 7d windows). Schema mirrors worktale.

Activity Log

Live tail of every internal action — git invocations, sidecar IPC, agent tool calls, FS watcher events. Filter by level, search by target. The IDE never lies about what it's doing.

Local-first

Your code, your sessions, your credentials — all on your disk in SQLite. Bring your own Anthropic and OpenAI keys. No telemetry. No remote runtime. No lock-in.

The loop

Plan, branch, generate, review — all in one window.

Winthorpe is the IDE for the part of the job that nobody else built tooling for: the workflow around the prompt. Agents do the typing. You decide what runs where, review the diff, ship the PR.

  • 1 Spin up a workspace. A new git worktree, a fresh branch, a session ready to take a prompt.
  • 2 Pick your agent. Claude Code or Codex CLI — same chat surface, same tool stream.
  • 3 Inspect and edit live. File tree, change list, hover-zoom terminal — and a built-in Monaco editor for the lines you want to tighten yourself before the commit.
  • 4 Open the PR. One click via the bundled gh/glab CLIs — no browser context-switch.
